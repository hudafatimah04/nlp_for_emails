# PRD coverage audit

This audit covers the 17 cases in [PRD Section 12](../PRD.md#12-error-handling-and-edge-cases) and the eight scenarios in [PRD Section 18](../PRD.md#18-demonstration-and-acceptance-criteria). The original audit suite ran with `python -m pytest -p no:cacheprovider -q -rs` and returned **242 passed, zero skipped**, including real local Tesseract on a generated PDF. The affected rows below now cite the LLM-only implementation. Gmail and backend calls in the cited tests use mocks. No live Gmail or backend calls were made for this audit.

A row is **covered by automated test** when a cited assertion proves the edge-case behavior at the stated boundary. **Partially covered** means evidence proves only part of the scenario. Section 18 includes a two-account Gmail demonstration, so offline assertions count as partial evidence for those complete scenarios, even where they prove the expected local outcome. **Covered by manual live test only** requires a recorded live run with a result. **Not covered** means no evidence was found. The repository contains instructions and examples for live use, but no recorded two-account acceptance run.

## Gaps ordered by risk

1. **Duplicate writes and source-row reuse.** The receiver's idempotency, duplicate response, and reuse of an existing source email are still pending in the [database integration contract](database_integration_contract.md). Verify a repeated handoff and a new opportunity from the same email against the backend before relying on live retries.
2. **Incorrect OCR can look valid.** Test degraded scans whose output changes a deadline or eligibility value into a plausible value. Verify the resulting review or handoff decision. Current partial-page tests exercise detectable failure.
3. **Live PDF-to-JSON path and provenance.** Document the two-account demonstration. Include an internship whose body and PDF provide distinct fields, a scanned brochure, and an email with several supported attachments. Verify file-to-opportunity links, nulls, and conflict candidates in final JSON.
4. **Gmail recovery during polling.** Verify an interrupted poll can recover on a subsequent iteration, including a connection failure and revoked authorization. Current evidence proves request-level retry and mocked reauthorization separately.
5. **Multiple announcements within one document.** Test whether two announcements in one body or one PDF can be represented separately. The verified multi-opportunity cases use separate attachments.
6. **Blank body with a usable attachment.** Test the full email-to-JSON path for a qualifying attachment with an empty body. Current evidence covers the empty-body parser and attachment-driven classification separately.
